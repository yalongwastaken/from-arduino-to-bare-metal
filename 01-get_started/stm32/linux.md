# STM32 Setup — Linux / Ubuntu 26.04 (STM32CubeIDE)

This guide gets you from zero to a working STM32 development environment for the Nucleo-F446RE on Ubuntu 26.04. Complete this before attempting any STM32 lesson in this repo.

---

## 1. Install STM32CubeIDE

STM32CubeIDE is ST's official IDE — it bundles a GCC-based toolchain, ST-Link flashing, CubeMX pin configuration, and a debugger in one install.

Download the **Linux x86_64 generic installer** (`.sh.zip`) from ST: [STM32CubeIDE](https://www.st.com/en/development-tools/stm32cubeide.html) (free, requires ST account).

> **Ubuntu 26.04 note — use the generic `.sh`, not the `.deb`.** The Debian package declares legacy dependencies (`libncurses5`, `libpython2.7`, `libwebkit2gtk-4.0-37`) that no longer exist in Ubuntu 24.04+ and will fail with "unmet dependencies / held broken packages." The generic installer sidesteps this entirely.

```bash
unzip en.st-stm32cubeide_*_amd64.sh.zip
chmod +x st-stm32cubeide_*_amd64.sh
sudo ./st-stm32cubeide_*_amd64.sh
```

Accept the license; use the default install path (`/opt/st/stm32cubeide_x.x.x/`). When asked, allow it to install the ST-Link server.

### Launch

```bash
/opt/st/stm32cubeide_*/stm32cubeide
```

> **Ubuntu 26.04 is a Wayland-only GNOME session — this matters.** STM32CubeIDE (Eclipse/SWT) is known to freeze or stop repainting under native Wayland, usually when you switch focus back to the IDE. Force it through XWayland by setting `GDK_BACKEND=x11`. The cleanest fix is a launch wrapper:
> ```bash
> #!/usr/bin/env bash
> export GDK_BACKEND=x11
> exec /opt/st/stm32cubeide_*/stm32cubeide "$@"
> ```
> Or one-off: `GDK_BACKEND=x11 /opt/st/stm32cubeide_*/stm32cubeide`

### Verify

STM32CubeIDE launches without errors. Connect your Nucleo-F446RE over USB — it should appear as an ST-Link device.

## 2. ST-Link Driver (udev rules)

The IDE bundles the ST-Link GDB server, but on Linux you also need **udev rules** so it can access the Nucleo without root. Copy them from the CubeIDE plugin directory:

```bash
CUBEIDE_DIR=$(ls -d /opt/st/stm32cubeide_*)
RULES_DIR=$(find "$CUBEIDE_DIR" -path "*stlink-gdb-server*/tools/udev/rules.d" -type d | head -1)

sudo cp "$RULES_DIR"/*.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
sudo udevadm trigger
```

Then add yourself to `dialout` (for the virtual COM port) and log out / back in:

```bash
sudo usermod -aG dialout $USER
```

> If `find` returns nothing, locate the rules manually: `find /opt/st -name "*.rules" 2>/dev/null`

## 3. Project Structure

Each STM32 lesson in this repo follows the standard STM32CubeIDE project layout generated by CubeMX:

```
2.1-hello_led/
└── stm32/
    ├── hello_led.ioc           — CubeMX configuration; regenerate code from this
    ├── Core/
    │   ├── Inc/
    │   │   └── main.h
    │   └── Src/
    │       └── main.c          — application entry point, HAL init, main loop
    ├── Drivers/
    │   └── STM32F4xx_HAL_Driver/ — HAL driver source (generated)
    ├── .cproject
    ├── .project
    └── README.md
```

### How the files relate

**`hello_led.ioc`**
The CubeMX configuration file — pinout, clocks, peripheral setup. This is the source of truth; **Project → Generate Code** regenerates `main.c`/`main.h` from it.

**`Core/Src/main.c`**
Your application code. HAL initialization happens in `main()` before the `while(1)` loop. Think of everything before the loop as Arduino's `setup()`, and the `while(1)` as Arduino's `loop()`.

**`Core/Inc/main.h`**
Pin definitions and includes. CubeMX generates this — add your own `#define` aliases here for readability.

**`Drivers/`**
HAL driver source generated by CubeMX. Do not edit these files directly.

## 4. Creating a New Project

Each lesson's STM32 project is generated from scratch using CubeMX inside STM32CubeIDE:

1. Open STM32CubeIDE → **File → New → STM32 Project**
2. Search for **NUCLEO-F446RE** and select it
3. Name the project (match the lesson name, e.g. `hello_led`)
4. Set **Targeted Language** to C
5. Configure pins in the CubeMX perspective
6. Click **Project → Generate Code**

---

## 5. Build and Flash

### Build
**Project → Build Project** or `Ctrl+B`

### Flash
Connect the Nucleo-F446RE over USB, then **Run → Run** (the green ▶ button). ST-Link programs the board automatically — no separate flash tool needed.

> Note: by default `F11` launches **Debug**, not Run. Use the green ▶ Run button (or **Run → Run**) for a plain flash-and-go.

### Serial Monitor
The Nucleo has a built-in USB-to-UART bridge on USART2. Open a serial monitor at **115200 baud** on the Nucleo's virtual COM port (`/dev/ttyACM0`) to see `printf` output.

## 6. Common Pitfalls

**IDE freezes / window stops repainting**
Wayland incompatibility on Ubuntu 26.04. Launch with `GDK_BACKEND=x11` (see section 1).

**Blank/white panel in some dialogs**
The IDE embeds a WebKit view for certain panels. Install: `sudo apt install libwebkit2gtk-4.1-0`

**ST-Link needs root / "ST-LINK not found"**
The udev rules aren't installed (section 2), or you haven't logged out since joining `dialout`.

**Board not detected**
Try a different USB cable — many cables are charge-only. The Nucleo should appear as an ST-Link device.

**Build errors after CubeMX regeneration**
CubeMX overwrites generated files — always keep your application code inside the `/* USER CODE BEGIN */` / `/* USER CODE END */` guards so it survives regeneration.

**`printf` not working over UART**
Retarget `_write` to USART2, or use `HAL_UART_Transmit` directly. CubeMX doesn't wire `printf` to UART by default.

**Flash fails with "No target connected"**
Hold the reset button on the Nucleo while initiating the flash, release after it starts.
