# STM32 Setup (STM32CubeIDE)

This guide gets you from zero to a working STM32 development environment for the Nucleo-F446RE. Complete this before attempting any STM32 lesson in this repo.

---

## 1. Install STM32CubeIDE

STM32CubeIDE is ST's official IDE — it bundles a GCC-based toolchain, ST-Link flashing, CubeMX pin configuration, and a debugger in one install.

Download from ST: [STM32CubeIDE](https://www.st.com/en/development-tools/stm32cubeide.html) (free, requires ST account)

Available for macOS, Linux, and Windows.

### Verify

Open STM32CubeIDE and confirm it launches without errors. Connect your Nucleo-F446RE over USB — it should appear as an ST-Link device.

---

## 2. Install ST-Link Drivers

### macOS / Linux
Drivers are included with STM32CubeIDE. No additional install needed.

### Windows
Install the [ST-Link USB driver](https://www.st.com/en/development-tools/stsw-link009.html) if the Nucleo isn't recognized.

---

## 3. Project Structure

Each STM32 lesson in this repo follows the standard STM32CubeIDE project layout generated by CubeMX:

```
2.1-hello_led/
└── stm32/
    ├── Core/
    │   ├── Inc/
    │   │   └── main.h
    │   └── Src/
    │       └── main.c          — application entry point, HAL init, main loop
    ├── Drivers/
    │   └── STM32F4xx_HAL_Driver/ — HAL driver source (generated)
    ├── .cproject
    ├── .project
    └── README.md
```

### How the files relate

**`Core/Src/main.c`**
Your application code. HAL initialization happens in `main()` before the `while(1)` loop. Think of everything before the loop as Arduino's `setup()`, and the `while(1)` as Arduino's `loop()`.

**`Core/Inc/main.h`**
Pin definitions and includes. CubeMX generates this — add your own `#define` aliases here for readability.

**`Drivers/`**
HAL driver source generated by CubeMX. Do not edit these files directly.

## 4. Creating a New Project

Each lesson's STM32 project is generated from scratch using CubeMX inside STM32CubeIDE:

1. Open STM32CubeIDE → **File → New → STM32 Project**
2. Search for **NUCLEO-F446RE** and select it
3. Name the project (match the lesson name, e.g. `hello_led`)
4. Set **Targeted Language** to C
5. Configure pins in the CubeMX perspective
6. Click **Project → Generate Code**

---

## 5. Build and Flash

### Build
**Project → Build Project** or `Cmd+B` / `Ctrl+B`

### Flash
Connect the Nucleo-F446RE over USB, then:
**Run → Run** or `F11`

ST-Link programs the board automatically. No separate flash tool needed.

### Serial Monitor
The Nucleo has a built-in USB-to-UART bridge on USART2. Open a serial monitor at 115200 baud on the Nucleo's virtual COM port to see `printf` output.

---

## 6. Common Pitfalls

**Board not detected**
Try a different USB cable — many cables are charge-only. The Nucleo should appear as an ST-Link device in your OS.

**Build errors after CubeMX regeneration**
CubeMX overwrites `main.c` — always keep your application code inside the `/* USER CODE BEGIN */` / `/* USER CODE END */` guards so it survives regeneration.

**`printf` not working over UART**
Retarget `_write` to USART2, or use `HAL_UART_Transmit` directly. CubeMX doesn't wire `printf` to UART by default.

**Flash fails with "No target connected"**
Hold the reset button on the Nucleo while initiating the flash, release after it starts.
