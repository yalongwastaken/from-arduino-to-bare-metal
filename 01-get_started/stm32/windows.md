# STM32 Setup — Windows 11 (STM32CubeIDE)

This guide gets you from zero to a working STM32 development environment for the Nucleo-F446RE on Windows 11. Complete this before attempting any STM32 lesson in this repo.

---

## 1. Install STM32CubeIDE

STM32CubeIDE is ST's official IDE — it bundles a GCC-based toolchain, ST-Link flashing, CubeMX pin configuration, and a debugger in one install. Windows is the smoothest STM32CubeIDE experience: everything is signed and the installer wires up drivers automatically.

Download the **Windows** installer (`.exe`) from ST: [STM32CubeIDE](https://www.st.com/en/development-tools/stm32cubeide.html) (free, requires ST account).

### Install steps

1. Right-click the installer → **Run as administrator**
2. Accept the license, keep the default install path
3. Leave all components checked — the **ST-Link USB drivers** and toolchain install as part of this

### Verify

Launch STM32CubeIDE from the Start Menu and confirm it opens without errors. Connect your Nucleo-F446RE over USB — it should appear as an ST-Link device.

---

## 2. ST-Link Driver

On Windows the ST-Link driver is installed automatically by the STM32CubeIDE installer (step 1). To confirm: plug in the Nucleo, open **Device Manager**, and look under **Universal Serial Bus devices** for **STM32 STLink** and under **Ports (COM & LPT)** for **STMicroelectronics STLink Virtual COM Port**.

If either shows a yellow warning icon, right-click → **Update Driver**, or install the standalone [ST-Link driver (STSW-LINK009)](https://www.st.com/en/development-tools/stsw-link009.html) as a fallback.

## 3. Project Structure

Each STM32 lesson in this repo follows the standard STM32CubeIDE project layout generated by CubeMX:

```
2.1-hello_led/
└── stm32/
    ├── hello_led.ioc           — CubeMX configuration; regenerate code from this
    ├── Core/
    │   ├── Inc/
    │   │   └── main.h
    │   └── Src/
    │       └── main.c          — application entry point, HAL init, main loop
    ├── Drivers/
    │   └── STM32F4xx_HAL_Driver/ — HAL driver source (generated)
    ├── .cproject
    ├── .project
    └── README.md
```

### How the files relate

**`hello_led.ioc`**
The CubeMX configuration file — pinout, clocks, peripheral setup. This is the source of truth; **Project → Generate Code** regenerates `main.c`/`main.h` from it.

**`Core/Src/main.c`**
Your application code. HAL initialization happens in `main()` before the `while(1)` loop. Think of everything before the loop as Arduino's `setup()`, and the `while(1)` as Arduino's `loop()`.

**`Core/Inc/main.h`**
Pin definitions and includes. CubeMX generates this — add your own `#define` aliases here for readability.

**`Drivers/`**
HAL driver source generated by CubeMX. Do not edit these files directly.

## 4. Creating a New Project

Each lesson's STM32 project is generated from scratch using CubeMX inside STM32CubeIDE:

1. Open STM32CubeIDE → **File → New → STM32 Project**
2. Search for **NUCLEO-F446RE** and select it
3. Name the project (match the lesson name, e.g. `hello_led`)
4. Set **Targeted Language** to C
5. Configure pins in the CubeMX perspective
6. Click **Project → Generate Code**

---

## 5. Build and Flash

### Build
**Project → Build Project** or `Ctrl+B`

### Flash
Connect the Nucleo-F446RE over USB, then **Run → Run** (the green ▶ button). ST-Link programs the board automatically — no separate flash tool needed.

> Note: by default `F11` launches **Debug**, not Run. Use the green ▶ Run button (or **Run → Run**) for a plain flash-and-go.

### Serial Monitor
The Nucleo has a built-in USB-to-UART bridge on USART2. Open a serial monitor at **115200 baud** on the Nucleo's virtual COM port (check Device Manager for the COM number) to see `printf` output.

## 6. Common Pitfalls

**Board not detected**
Try a different USB cable — many cables are charge-only. The Nucleo should appear as an ST-Link device in Device Manager.

**ST-Link shows a yellow warning in Device Manager**
Right-click → Update Driver, or install STSW-LINK009 (section 2).

**Build errors after CubeMX regeneration**
CubeMX overwrites generated files — always keep your application code inside the `/* USER CODE BEGIN */` / `/* USER CODE END */` guards so it survives regeneration.

**`printf` not working over UART**
Retarget `_write` to USART2, or use `HAL_UART_Transmit` directly. CubeMX doesn't wire `printf` to UART by default.

**Flash fails with "No target connected"**
Hold the reset button on the Nucleo while initiating the flash, release after it starts.
