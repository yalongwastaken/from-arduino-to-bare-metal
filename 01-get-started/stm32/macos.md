# STM32 Setup — macOS (STM32CubeIDE)

This guide gets you from zero to a working STM32 development environment for the Nucleo-F446RE on Apple Silicon. Complete this before attempting any STM32 lesson in this repo.

---

## 1. Install STM32CubeIDE

STM32CubeIDE is ST's official IDE — it bundles a GCC-based toolchain, ST-Link flashing, CubeMX pin configuration, and a debugger in one install.

Download the **macOS** package (`.dmg`) from ST: [STM32CubeIDE](https://www.st.com/en/development-tools/stm32cubeide.html) (free, requires ST account).

> **There is no native Apple Silicon build.** ST ships an x86_64 build only; it runs on M-series Macs through **Rosetta 2**. It works well in practice, but expect Gatekeeper friction during install because the package isn't App Store–notarized.

### Install steps

1. Install Rosetta 2 up front so the installer doesn't stall:
   ```bash
   softwareupdate --install-rosetta --agree-to-license
   ```
2. Open the `.dmg`. It contains two items — run the **`st-stlink-server` `.pkg` first** (this installs the ST-Link driver/server), then drag the **STM32CubeIDE app** onto the Applications symlink. macOS will block the `.pkg` initially: **System Settings → Privacy & Security → Open Anyway**, then re-run it.
   > The IDE icon sometimes sits below the fold in the `.dmg` window — scroll down if you only see the `.pkg`.
3. First launch usually throws *"STM32CubeIDE is damaged and can't be opened"* — a Gatekeeper quarantine artifact, not actual damage. Clear it:
   ```bash
   xattr -dr com.apple.quarantine /Applications/STM32CubeIDE.app
   ```
   (Or right-click the app → **Open** → **Open Anyway**.)

### Verify

Launch STM32CubeIDE and confirm it opens without errors. Connect your Nucleo-F446RE over USB — it should appear as an ST-Link device.

## 2. ST-Link Driver

On macOS the ST-Link driver/server is the **`st-stlink-server` `.pkg`** bundled inside the `.dmg` — you installed it in step 1 above. No separate download is needed; if flashing fails, re-run that `.pkg` from the disk image.

## 3. Project Structure

Each STM32 lesson in this repo follows the standard STM32CubeIDE project layout generated by CubeMX:

```
2.1-hello-led/
└── stm32/
    ├── hello_led.ioc           — CubeMX configuration; regenerate code from this
    ├── Core/
    │   ├── Inc/
    │   │   └── main.h
    │   └── Src/
    │       └── main.c          — application entry point, HAL init, main loop
    ├── Drivers/
    │   └── STM32F4xx_HAL_Driver/ — HAL driver source (generated)
    ├── .cproject
    ├── .project
    └── README.md
```

### How the files relate

**`hello_led.ioc`**
The CubeMX configuration file — pinout, clocks, peripheral setup. This is the source of truth; **Project → Generate Code** regenerates `main.c`/`main.h` from it.

**`Core/Src/main.c`**
Your application code. HAL initialization happens in `main()` before the `while(1)` loop. Think of everything before the loop as Arduino's `setup()`, and the `while(1)` as Arduino's `loop()`.

**`Core/Inc/main.h`**
Pin definitions and includes. CubeMX generates this — add your own `#define` aliases here for readability.

**`Drivers/`**
HAL driver source generated by CubeMX. Do not edit these files directly.

## 4. Creating a New Project

Each lesson's STM32 project is generated from scratch using CubeMX inside STM32CubeIDE:

1. Open STM32CubeIDE → **File → New → STM32 Project**
2. Search for **NUCLEO-F446RE** and select it
3. Name the project (match the lesson name, e.g. `hello_led`)
4. Set **Targeted Language** to C
5. Configure pins in the CubeMX perspective
6. Click **Project → Generate Code**

---

## 5. Build and Flash

### Build
**Project → Build Project** or `Cmd+B`

### Flash
Connect the Nucleo-F446RE over USB, then **Run → Run** (the green ▶ button). ST-Link programs the board automatically — no separate flash tool needed.

> Note: by default `F11` launches **Debug**, not Run. Use the green ▶ Run button (or **Run → Run**) for a plain flash-and-go.

### Serial Monitor
The Nucleo has a built-in USB-to-UART bridge on USART2. Open a serial monitor at **115200 baud** on the Nucleo's virtual COM port to see `printf` output.

## 6. Common Pitfalls

**"STM32CubeIDE is damaged and can't be opened"**
Gatekeeper quarantine. Run `xattr -dr com.apple.quarantine /Applications/STM32CubeIDE.app`, or right-click → Open → Open Anyway.

**Board not detected**
Try a different USB cable — many cables are charge-only. The Nucleo should appear as an ST-Link device.

**Build errors after CubeMX regeneration**
CubeMX overwrites generated files — always keep your application code inside the `/* USER CODE BEGIN */` / `/* USER CODE END */` guards so it survives regeneration.

**`printf` not working over UART**
Retarget `_write` to USART2, or use `HAL_UART_Transmit` directly. CubeMX doesn't wire `printf` to UART by default.

**Build script fails looking for `md5sum` or similar**
A `PATH` issue — Homebrew installs to `/opt/homebrew/bin` on Apple Silicon, which CubeIDE's environment may not pick up. Add it to the IDE's launch environment or your shell profile.

**Flash fails with "No target connected"**
Hold the reset button on the Nucleo while initiating the flash, release after it starts.
